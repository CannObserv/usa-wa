# Modules — the roster-PDF source (#225, epic #219)

Layer 3, `packages/usa-wa-adapter-legislature/src/usa_wa_adapter_legislature/roster_pdf/`:
**source 2** of the WA Legislature adapter, split out of
[MODULES-LEGISLATURE.md](MODULES-LEGISLATURE.md) once the #226 succession chain landed. The SOAP
half of the package is there; the tenure-span and operator-succession half is in
[MODULES-LEGISLATURE-SPANS.md](MODULES-LEGISLATURE-SPANS.md).

The WA Legislature's own *Members of the Legislature 1889-2025* roster PDF
(`usa_wa_legislature_roster`, 233pp, revision 2025-06-05). Its unique value is **102 years
below the WSL SOAP floor** plus the **exact mid-term succession dates** every live wire
structurally lacks, since spans are biennium-quantized.

They differ in kind, not just in endpoint: SOAP is a daily API, the roster is a **frozen
document revised about twice a decade**, so it is harvested by hand, re-checked monthly by a
dry-run timer (#237), never joins the nightly harvests, and is never authoritative for the current
biennium (it lags it by design).

## Phases

`raw_harvest` (A) archives one edition · the pipeline's roster staging re-parses it offline
through `extraction` + `normalize` (B) · `identity` → `projector` + `oracle` feed the conformed
spans ([MODULES-LEGISLATURE-ROSTER-BUILD.md](MODULES-LEGISLATURE-ROSTER-BUILD.md)), `projector`
reading `succession`'s parsed clauses · `audit` read only. The Postgres half — `adapter`,
`cohort`, `harvest` and the #226 write side `backfill` — was deleted in #412 PR F; the
`succession` proposal layer and `resolve` it orphaned went in #471.

```
  roster_pdf/
    coverage.py   — one claim, `member_roster` **verified 1889-2025** — deliberately **CLOSED**, unlike every sibling feed. This source is a revision snapshot that cannot see past its own stamp, so an open-ended claim would assert coverage of a biennium it lags. Precedence: the roster wins for closed biennia below the WSL floor; operator events + WSL/SOS win at and above it
    transport.py  — `RosterPdfClient`: fetch + sha256. **No cache validators** on the response (no `ETag`/`Last-Modified`/`Cache-Control`, verified live), so change detection is a full GET + content hash — ~69MB/yr at the monthly re-check (#237). A **404 means re-discover the href** from the Legislative Information Center index, because `s4gf4suc` is a CMS-minted media key a re-publish is expected to rotate; any other status propagates, since treating a 500 as a rotated key would mask a real outage. **Courtesy limiter (#236)**: every `leg.wa.gov` request, redirect hops included, waits on `_LEG_LIMITER` through an httpx request hook rather than per call site, dispatched via `asyncio.to_thread` because `RateLimiter` blocks; knob + `--pause-seconds`: [ENVIRONMENT.md](ENVIRONMENT.md)
    resources.py  — `legroster:<revision-date>` prefix, builder and parser (#412). The key is the document's own *Revision Date*, so it means "this edition", not "this fetch"; one key per revision is also the citation granularity (settled on #219): a 1943 row cites `legroster:2025-06-05`. Pure; shared by `raw_harvest` and the pipeline's roster staging
    extraction.py — the **single `pdfplumber` boundary**: bytes → word geometry (`extract_pages`) + the edition's own `Revision Date` (`extract_revision_date`). Its own module so `normalize` stays pure; `edition` reads the stamp through it and the pipeline's roster staging the pages
    normalize.py  — **the parser, pure over word bounding boxes rather than text.** The layout defeats text extraction three ways — two columns per page, a year gutter the extractor treats as a separate cell, and annotations that wrap and can themselves end in dots + a party letter — so a naive line parse recovers **464 of 8,485 rows (5%)**. Rows reassemble by y-coordinate within an x-bounded column. Three shapes the real document forced: the **party token, not paren balance, terminates a row** (the source contains an unclosed paren at LD25 2021 that otherwise swallows the rest of the column); the **dot leader is optional** (a long annotation consumes it); and **year state threads across column and page breaks, per chamber** (#252): the state is a dict keyed by chamber, saved/restored at every divider crossing, because a page can interleave two blocks across its columns — the Senate block's tail in the right column's top above the House block's continuation — and a single scalar carried the wrong block's year onto a year-less successor row (C. W. Beck's 1974 appointment emitted as an 1899 senator). Two sibling #252 classes: a row that wraps *before* its dotted leader is held accumulating until the party token arrives (Newschwander's 1969 Senate term vanished; its debris glued onto an 1899 House row), and the footer band sits at 0.94 of page height — measured: content reaches 0.9205, the printed footer starts at 0.9646 — because 0.909 cut the bottom line of every full page (~60 printed rows, among them Frances Swayze, whose resignation the parse pinned on the wrong member). Known residual: one cluster-merged 1987 row (LD43, Niemi) still collapses its group into 1985. Section bounds come from the district banners, never a page range — districts run 1-60, so a fixed window truncates the tail. **Chamber is a full-width y-divider, not a page property** (#233): a district's Senate and House blocks routinely share one page — **35 of the 166 district pages** — so the chamber is resolved per row from the most recent `SENATE` / `HOUSE OF REPRESENTATIVES` banner above it, and crossing one resumes that chamber's own year sequence (fresh at the district's floor on first entry, #252). Reading it once from the running header filed every row below a mid-page banner under the wrong chamber, which is how the 1913 Socialist became a senator; because `Ind` folds to no party, that both invented an assignment and discarded a real one. Caught by the Brazier cross-check (#233), not by the audit oracle — whose match rate actually *improves* under the bug, since a Senate row covers a four-year term and a House row two, so mislabelled rows over-cover claims. Treat that rate as a floor on disagreement, never as a score to maximise. Party tokens are carried **verbatim**; folding an unknown one to `None` is the silent-drop bug #227 exists to prevent. **`_ROW_PARTY` is a closed alternation over `PARTY_TOKENS`, which relocated that bug one layer up** (#227 CR): a row whose abbreviation the source newly introduces fails the party match, fails the prose test, and was dropped by the silent-furniture branch — never reaching `unparsed`, so `usa_wa_common.parties`' `unknown_token` disposition could not fire from this path and #227's oracle reported a clean run over exactly the records that survived the parse. `_has_undeclared_party_tail` detects member-row *shape* (dot leader + short trailing token, one interior space so `Silver Rep.` qualifies, no dot runs inside the tail so a repeated leader resolves to its real token) and routes such a line to `unparsed` instead. Measured against the archived edition: **0 lines**, so it adds no noise and fires only on a genuinely new token. **Coverage is not total, by construction** (CR #59): the leader is optional in this source, so the threshold sits at two dots (measured identically clean to three, and the source does typeset `..D`) and the **13 of 4,601** token-terminated lines with no leader at all — 0.3% — remain invisible. A new abbreviation landing on one of those is still dropped; closing it needs a signal other than the leader. A conformance test pins `PARTY_TOKENS` ⊆ what the vocabulary can classify — it caught `Soc.` and the dotless `Ind` sitting in the unclassified bucket. Measured on the full document after #252: **8,584 records, 1889-2025, 53 districts, 1,046 annotated, 0 unparsed**
    provisioning.py — get-or-create the `usa_wa_legislature_roster` `Source` (`kind="document"`, archival retention, 90-day TTL) + seed its claim on both paths; called nightly by `usa_wa_pipeline.coverage_seed`. A distinct row from the WSL SOAP source: same jurisdiction and target, different publisher and archive
    audit.py      — **the read-only oracle** (#225 Phase 1), pure, run from tests and by hand (`TERM_YEARS` is what `identity` and `projector` import from it): partitions our own `(name, district, chamber, year)` claims into what the roster attests and what it does not. Unattested is a *candidate artifact*, never a deletion — below the roster's floor, absence is silence rather than denial. Matching folds honorifics/nicknames/initials via `usa_wa_common.names` (`Robert "Bob" McCaslin` ≡ `Bob McCaslin`), and a roster row **covers the term it opens** (`TERM_YEARS`: house 2, senate 4) — the roster lists a member only in the year their term *begins*, so exact-year matching marked ~half of all Senate claims unattested by construction. Live result: **2,064 claims, 98.0% attested**, and it independently reproduces both #144 findings with no hand-curation — Wynne's LD39 Senate 2001 flagged (the roster has him in the LD39 *House* only) while Marlo Braun's LD20 Senate 2017 is confirmed, dated to a five-day substitution a biennium-quantized span cannot express
    succession.py — **#226 read side**, pure — `parse_annotation` splits a roster annotation into clauses, each with its verb and the most precise date it states; `projector` reads them to refine successor coverage at biennium grain. Two refusals rather than guesses: **state the precision, never round it** (`Deceased July 1977` is real — only a `day`-precision `ParsedDate` carries a `value`; coarser ones carry a `window`, #360) and **a session reference is not a date** (`Appointed to serve 1951 2nd Ex. S.`, `Holdover from District 21, 1901 Session`). The operator-event proposal layer built on it (`propose_events`, `proposals_for_seat`) and the `resolve.py` resolver that gave proposals a member id and House Position fed the Postgres succession backfill; #412 PR F deleted the backfill and #471 deleted both (their measured design notes are in git history, at `3feb9a5`). `Seating`, the one live type `resolve.py` held, moved to `identity`
    edition.py    — `DEFAULT_REVISION` (the edition the code knows; bump it after archiving a new one), `RosterRevisionMismatch` and `verify_edition`, the stamp check (#421): the revision a run is told is verified against the fetched document's own stamp (CR finding 1) — the key claims to name an edition, so the bytes must be that edition; otherwise the next published edition fetched under a stale `--revision` archives as the old one and every citation minted from it names an edition that never attested the fact. Pure; used by `raw_harvest`
    raw_harvest.py — **Phase A** (`python -m usa_wa_adapter_legislature.roster_pdf.raw_harvest --revision 2025-06-05`, #421): fetch, verify the stamp, record `legroster:<revision>` into `raw/usa_wa_legislature_roster/`, the store the #302 roster staging model parses the newest edition from. On demand, never nightly; a 90-day `latest.json` freshness window makes a re-run fetch nothing, `--force` fetches past it, `--pause-seconds` sets the `leg.wa.gov` limiter. A new edition, an unlocatable document or an unreadable stamp exits `4` and writes nothing (the stamp is the only stale-edition guard and the re-check's only view of a new edition, #421 CR 4/6); an outage raises (exit `1`). Not built on `record_fetch`, which would flatten both exit-4 conditions into a generic `err` entry and cannot skip the write for a dry run. **The monthly re-check (#237)** is this module run `--dry-run --force` by `usa-wa-roster-pdf-recheck.timer`: fetch and verify only, never a raw-store run
```
