# Modules — Layer 4 deployment

`packages/usa-wa-api/` (the FastAPI deployment), `packages/usa-wa-sync-powermap/`
(the PM sync binding and sidecar daemon), and the
repo-root directories. The portable engine these bind is in
[MODULES-FRAMEWORK.md](MODULES-FRAMEWORK.md) and [MODULES-SYNC-ENGINE.md](MODULES-SYNC-ENGINE.md);
the one-shot producer CLIs the daemon does not run are in
[MODULES-SYNC-PRODUCERS.md](MODULES-SYNC-PRODUCERS.md).

Since #181 that engine is a **package** — `clearinghouse_sync_powermap/engine/`
(`context` / `anchors` / `write` / `read` under a `SyncEngine` façade) — with the
import path and public surface unchanged, so every binding below calls it as before.
A module needing a subsystem directly reaches `engine.writer` / `engine.reader` /
`engine.anchors` rather than widening the façade.

**Every producer CLI runs on the #179b job harness** (`--dry-run`/`--json`, a `job_runs`
row). Their shared `0/1/2/3` mapping lives once in **`jobs.py`**: an abort is `degraded` on
`EXIT_ABORTED=3`, an auth block and rejected rows are `failed` on `2`/`1`. Codes unchanged;
the auth diagnostic moved to stderr; all pass `commit=False`. The daemon `__main__.py` is
exempt (it has no terminal outcome).

PM echoes any withheld natural-key delta in `ObservationResult.unapplied` (parsed from the response's `additional_properties`, no client regen); the engine surfaces a non-empty set as an `observation_deltas_unapplied` WARNING + a `DrainStats.unapplied` tally in `sidecar_cycle_summary` (should stay 0 now anchored rows are id-addressed). Shared by bootstrap + `__main__` + every PM CLI
      sidecar.py      — Sidecar: per-cycle run (catalog sync → re-discovery backstop → per-descriptor reconciles → tick (feed → sweep → drain)) + isolated run loop. **Cycle-failure containment (#85, from the #84 postmortem)**: each descriptor's reconcile runs in its OWN session + error boundary (one poison entity can't roll back the other descriptors' reconcile stamps, the feed cursor, or the drain — the #84 amplification that generated ~1.7M reads over 4 days); every contained component failure still fails the cycle *verdict* (isolation must not defeat the retry signal), which drives exponential backoff in `run_forever` (`retry.backoff`: 60s base → 1h cap, reset on a clean cycle) and the **failure-streak alert** — the sidecar is a `Restart=` service the #49 `OnFailure=` handler can't see, so after `FAILURE_ALERT_THRESHOLD` (default 5 ≈ ~30 min) consecutive failed cycles it emails the operator once per streak via the injected `alert` callable. **Rejection visibility (#85)**: a `sidecar_cycle_summary` INFO line every cycle (outbox backlog + REJECTED reason breakdown via `engine.rejected_breakdown`) and one email when the REJECTED count *rises* (static pile never re-spams; the #84 case — 12 `identifier_conflict` rejections unnoticed for a week — now alerts on arrival). **Disposition + orphan-mint visibility (#108)**: the same summary line carries the last drain's per-disposition counts (`dispositions`, `new`/`auto-attached`/…) and its `reanchors` tally (in-place anchor overwrites = orphaned PM ids this cycle, each recorded in `AnchorReanchor`) — 88 orphaned assignments were minted in 24h with no operator-visible number changing. `tick` stashes `engine.last_drain_stats` (reset per drain) for the summary to read in its own session. **Non-convergence visibility (#112)**: the same summary line carries `non_converging` (the `nonconverging_count` standing count of rows at/over `nonconvergence_threshold`) and emails once when it *rises* (the #85 rejection-rise pattern) — a fourth silent producer→PM churn cohort (after #110's three) is now surfaced + alerted on arrival instead of found by a manual outbox audit days later. **Stalled-push visibility (#247)**: the summary carries `local_newer_forced` — anchored rows whose local clock had passed their stored watermark — a local-only change PM has not seen (rows re-fetched only because their validator predates the watermark are excluded, so the first post-migration cycle is not a false backlog). Every other field on the line counts work already in flight, so a cohort whose push half has stopped scores zero across all of them and reads exactly like one fully converged; that is how #247's 397 stranded assignment spans survived six clean-looking cycles. Read the *sustained* value, not the spike: a large one-off after a backfill is the system working, the same number every cycle is a wedged push. **Changes-feed replay backstop (#159, re-costed #211)**: `_run_replay` runs the engine's `replay_from_floor` in its own session + error boundary (like `_run_reconciles`), cadence-gated on `REPLAY_STREAM` (`_replay_due`, `replay_cadence` default 1h) and kill-switchable (`replay_enabled`). **The cadence runs from pass END (#211)**: `_stamp_replay_completed` overwrites the engine's cycle-start stamp with a fresh clock read after the pass, so a long pass can never make itself immediately due again — duty cycle bounded < 100% by construction (passes are also strictly sequential in-process, so literal overlap is impossible); a pass running ≥ the cadence logs `sidecar_replay_overrun` (the loud half — the pre-#211 back-to-back stacking was silent and held PM at its 2 req/s ceiling for 19h). The `sidecar_replay` line carries the per-pass budget observables (`items`, `budget_exhausted`, `duration_seconds`). Its `ReplayResult` rides the `sidecar_cycle_summary` line (`replay_healed`/`replay_applied`/`replay_fell_off`); a horizon fall-off emails once on the rising edge (the #85 rise-alert shape) and calls `_force_anchored_rescan` (nulls the `anchored_cohort` descriptors' `reconcile:{type}` stamps so the full scan — the only cover for the pruned slice — runs next cycle regardless of its cadence). **Rollout is phased**: Phase A (shipped default) runs replay in *shadow* alongside the unchanged 12h anchored scan, so the would-heal delta is measured against the scan still being the live safety net; Phase B *widens* the scan to the residual-only weekly cadence via the operational env flip `RECONCILE_CADENCE=168h` — gated on Phase-A evidence (`replay_healed` covering what the scan catches + `replay_fell_off` staying false), NOT a code default change

Mechanical rule — *if a test never constructs a `Sidecar`, it does not belong there*; the engine is specified in `clearinghouse-sync-powermap`'s own suite against the jurisdiction-free `testing.py` harness, since a Layer-2 behaviour specified from Layer 4 is one a sibling jurisdiction would not inherit. **AR-9's premise did not survive the audit.** The co-change is real (14 of the last 300 engine commits also touched this file, vs 8 for the engine's write suite) but is not a misplaced specification: of 56 tests / 106 assertions, exactly **one** test (2 assertions) drove a bare `SyncEngine` with no `Sidecar` — migrated to `test_engine_read.py::test_reimported_record_does_not_reenqueue_writeback`. Every other engine behaviour the file touches (drain chunking, sweep batch commit, anchored-cohort recovery + cadence stamp, clock adoption, the `>= threshold` count, subscription backfill) is *already* specified generically; what remains asserts *composition*, this layer's job. The actual driver is a **producer/consumer pair across the layer boundary**: `sidecar_cycle_summary` is the sole consumer of every per-cycle statistic the engine emits, so each new counter (#85, #108, #111, #112, #159, #160) necessarily changes engine + sidecar + this file together — 9 of the 14. The rest are transaction-boundary hooks (#8/#92/#93/#94) and one #86 fixture fix. That coupling is inherent to siting the observability surface at Layer 4; moving tests does not fix it.
