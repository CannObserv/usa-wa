# Modules — Layer 4 deployment

`packages/usa-wa-api/` (the FastAPI deployment), `packages/usa-wa-sync-powermap/`
(the PM sync binding and sidecar daemon, with its producer CLIs), and the
repo-root directories. The portable engine these bind is in
[MODULES-FRAMEWORK.md](MODULES-FRAMEWORK.md).

Since #181 that engine is a **package** — `clearinghouse_sync_powermap/engine/`
(`context` / `anchors` / `write` / `read` under a `SyncEngine` façade) — with the
import path and public surface unchanged, so every binding below calls it as before.
A module needing a subsystem directly reaches `engine.writer` / `engine.reader` /
`engine.anchors` rather than widening the façade.

**Every producer CLI below runs on the #179b job harness** (`--dry-run`/`--json`, a `job_runs`
row). Their shared `0/1/2/3` mapping lives once in **`jobs.py`**: an abort is `degraded` on
`EXIT_ABORTED=3`, an auth block and rejected rows are `failed` on `2`/`1`. Codes unchanged;
the auth diagnostic moved to stderr; all pass `commit=False`. The daemon `__main__.py` is
exempt (it has no terminal outcome).

every contained component failure still fails the cycle *verdict* (isolation must not defeat the retry signal), which drives exponential backoff in `run_forever` (`retry.backoff`: 60s base → 1h cap, reset on a clean cycle) and the **failure-streak alert** — the sidecar is a `Restart=` service the #49 `OnFailure=` handler can't see, so after `FAILURE_ALERT_THRESHOLD` (default 5 ≈ ~30 min) consecutive failed cycles it emails the operator once per streak via the injected `alert` callable. **Rejection visibility (#85)**: a `sidecar_cycle_summary` INFO line every cycle (outbox backlog + REJECTED reason breakdown via `engine.rejected_breakdown`) and one email when the REJECTED count *rises* (static pile never re-spams; the #84 case — 12 `identifier_conflict` rejections unnoticed for a week — now alerts on arrival). **Disposition + orphan-mint visibility (#108)**: the same summary line carries the last drain's per-disposition counts (`dispositions`, `new`/`auto-attached`/…) and its `reanchors` tally (in-place anchor overwrites = orphaned PM ids this cycle, each recorded in `AnchorReanchor`) — 88 orphaned assignments were minted in 24h with no operator-visible number changing. `tick` stashes `engine.last_drain_stats` (reset per drain) for the summary to read in its own session. **Non-convergence visibility (#112)**: the same summary line carries `non_converging` (the `nonconverging_count` standing count of rows at/over `nonconvergence_threshold`) and emails once when it *rises* (the #85 rejection-rise pattern) — a fourth silent producer→PM churn cohort (after #110's three) is now surfaced + alerted on arrival instead of found by a manual outbox audit days later. **Changes-feed replay backstop (#159)**: `_run_replay` runs the engine's `replay_from_floor` in its own session + error boundary (like `_run_reconciles`), cadence-gated on `REPLAY_STREAM` (`_replay_due`, `replay_cadence` default 1h) and kill-switchable (`replay_enabled`). Its `ReplayResult` rides the `sidecar_cycle_summary` line (`replay_healed`/`replay_applied`/`replay_fell_off`); a horizon fall-off emails once on the rising edge (the #85 rise-alert shape) and calls `_force_anchored_rescan` (nulls the `anchored_cohort` descriptors' `reconcile:{type}` stamps so the full scan — the only cover for the pruned slice — runs next cycle regardless of its cadence). **Rollout is phased**: Phase A (shipped default) runs replay in *shadow* alongside the unchanged 12h anchored scan, so the would-heal delta is measured against the scan still being the live safety net; Phase B *widens* the scan to the residual-only weekly cadence via the operational env flip `RECONCILE_CADENCE=168h` — gated on Phase-A evidence (`replay_healed` covering what the scan catches + `replay_fell_off` staying false), NOT a code default change

Guarded by empty-pull (either roster) + low-overlap (`--min-overlap-fraction`, default 0.5 — stable WSL Ids mean a healthy diff overlaps near-totally; a thin overlap = wrong-biennium pull, which would otherwise read as a hollow "renamed: 0") + rename-storm floor (`--max-rename-fraction`, default 0.34); skips unanchored + the live-cohort-absent (counted **hidden** = archived/deleted-but-produced vs **unproduced** = never-produced/other-source). Weekly timer (Sun 07:30 UTC, #53)
      reconcile_committee_meeting_names.py — one-shot producer CLI (#56): the meeting-derived sibling of #46, for the Joint/`Other` (`org_type='other'`) class `CommitteeService` can't see (#39; e.g. ESEC `Id 13945`). Same windowed emit + shared spine as #46, but **re-tuned guards** for a dormancy-prone cohort: low-overlap **off by default** (`--min-overlap-fraction` 0.0 — a body absent from one window is dormancy, not a wrong-biennium signal) and the storm fraction only weighed past `--storm-floor-min-overlap` (default 5). Window-absence ≠ rename (the diff intersects ids present in **both** windows). Weekly timer (Sun 07:45 UTC) + ad-hoc. Backfill caveat: the detector diffs current-vs-prior biennium, so an older rename (ESEC = 2023) needs a targeted `--biennium`

A genuine pending change (observation differs) is **left** for the reconcile — the heal must never drop a real update. App-role `canonical` write; read-only PM; `--dry-run`; exit 0/2/3. The **durable backstop** is the `apply_record` local-newer no-op gate (below); this heal is the one-shot convergence of the existing skew
      retract_assignments.py — one-shot producer retraction CLI (#144 Phase 2): given local assignment `source_id`s, retires each artifact tenure usa-wa produced (the Wynne LD39 Senate 2001-02 chamber-conflation + its paired party span) via power-map#391's `op:"retract"` on the assignment observation channel — POSTs `{identifier_type:pm_assignment_id, identifier_value:<ulid>, op:"retract"}` to `/api/v1/assignments/observations` (`op` rides the request model's `additional_properties`, the #111 pattern — no client regen), and on a `retracted` disposition tombstones the local row (`archived_at`, the reversible axis mirroring PM's archive — `_seat_scope` excludes archived rows so the `--sweep-biennia` audit clears). **Retraction is terminal** (power-map#391 shipped no reversible `archived:false`; un-retract is admin-only) — never build retry against un-retract; PM's anti-resurrection + the #144 Phase 1 derivation exclusion keep the phantom span from returning. An already-`archived_at` target (a completed prior run) is an idempotent `already_retracted` (no re-POST — resolve is full-natural-key `(source, source_id)` incl. archived, not `live_only`, so a re-run isn't mis-reported `not_found`); unanchored/not-found skipped-and-counted; a non-`retracted`/`auto-attached` disposition is `unexpected` + un-tombstoned. Transient 429/5xx retries on a bounded backoff (the heal pattern). App-role DML; `--source-id` (repeatable, required) + `--source` (default `usa_wa_legislature`) + `--dry-run` (resolves + previews WITHOUT POSTing — a retract POST is irreversible); exit 0 clean/idempotent · 1 a target unsettled (not-found/unanchored/refused) · 2 auth · 3 persistent transient PM outage (re-run). Run sidecar-paused
      prune_subscriptions.py — one-shot reclaim CLI (#73 Axis 1 step 6): the counterpart to `build_reconciler`'s mirror-set scoping. `sync_subscriptions` is additive (never unsubscribes), so the ~1,000 PM-only strangers the old whole-subtree walk registered stay subscribed-but-inert (feed delivers, reconciler fetch-then-skips). This diffs PM's `list_subscriptions` against the freshly-discovered mirror set (`SubscriptionReconciler.prune_subscriptions`) and `remove_subscriptions` the difference. Guarded against a discovery collapse: an empty desired-set (`empty_desired`) or a stale fraction over `--max-prune-fraction` (`prune_floor`, default 0.9 — permissive, since the first run legitimately removes ~half) aborts. Strangers have no local row, so nothing is evicted locally; idempotent. **Run-once**, not a timer.
