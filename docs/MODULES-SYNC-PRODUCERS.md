# Modules — PM producer CLIs

`packages/usa-wa-sync-powermap/src/usa_wa_sync_powermap/`, the one-shot producer CLIs
the sidecar does not run: reconcilers, heals, validation and retraction. The daemon,
its descriptors and the deployment they sit in are in [MODULES-SYNC.md](MODULES-SYNC.md);
the portable engine is in [MODULES-SYNC-ENGINE.md](MODULES-SYNC-ENGINE.md). How to run
each one: [COMMANDS-SYNC.md](COMMANDS-SYNC.md).

Every CLI here runs on the #179b job harness (`--dry-run`/`--json`, a `job_runs` row) —
the shared exit-code mapping is described in [MODULES-SYNC.md](MODULES-SYNC.md).

```
      reconcile_committee_active.py — one-shot producer CLI (#44): diffs the produced committee cohort against `CommitteeService.GetCommittees(biennium)` and reconciles PM `active` both ways — `active=false` for committees the roster dropped, `active=true` for ones that reappear (reactivation self-heals a modest partial-pull false retirement on the next clean run). Guarded by an empty-pull check + cohort floor (denominator = active cohort); skips archived/deleted/unanchored; emit-only (PM stays authority for `active`, mirrors it back — no local write). **Live-era scoping (#90)**: the diff is restricted to committees whose WSL `Id` appears in the current **or** immediately-prior biennium roster (`present_ids ∪ prior_ids`, the prior roster's raw `Id`s read archive-first via `CommitteeRosterCohortProvider`); the historical committee backfill (`committees/harvest.py`, model A) floods the produced cohort with ~152 defunct-era Ids (all defaulting `active=true`) that would otherwise read as a mass retirement and trip the floor every run — they now fall out before the diff (counted `scoped_out`) while a genuine prior-biennium retirement still fires. Weekly timer (Sun 07:00 UTC, #48) + ad-hoc; out-of-band from routine sync (`to_observation` keeps `active` out, #43)
      committee_name_reconcile.py — shared rename-detection spine (#46 + #56): given a current/prior `{source_id: name}` cohort it diffs on the stable id, runs the guardrails (empty-pull / low-overlap / rename-storm, the storm fraction gated by `storm_floor_min_overlap` so a tiny overlap can't hair-trigger it), and emits the windowed dated-name evidence via `OrganizationDescriptor.to_names_observation` (prior name typed `former`, new name `legal`, #58 — name_type is observation, not curation). The cohort name value is both **diffed and emitted**, so each caller controls which name reaches PM; cohort/`produced` queries are parametrized by `org_type`; emit-to-PM-only, no local write
      reconcile_committee_names.py — one-shot producer CLI (#46), the write-side sibling of #45's read mirror. Detects a WSL committee **rename** (stable `Id`, changed `LongName`) by diffing `GetCommittees(current)` vs `GetCommittees(prior)` on `normalize_name(LongName)` — WSL's own raw name, **not** the PM-resolved `Organization.name` scalar (which would false-fire on PM canonicalisation and miss round-tripped renames). Builds `{Id: LongName}` maps and delegates to `committee_name_reconcile` (org_type='committee'). Guarded by empty-pull (either roster) + low-overlap (`--min-overlap-fraction`, default 0.5 — stable WSL Ids mean a healthy diff overlaps near-totally; a thin overlap = wrong-biennium pull, which would otherwise read as a hollow "renamed: 0") + rename-storm floor (`--max-rename-fraction`, default 0.34); skips unanchored + the live-cohort-absent (counted **hidden** = archived/deleted-but-produced vs **unproduced** = never-produced/other-source). Weekly timer (Sun 07:30 UTC, #53)
      reconcile_committee_meeting_names.py — one-shot producer CLI (#56): the meeting-derived sibling of #46, for the Joint/`Other` (`org_type='other'`) class `CommitteeService` can't see (#39; e.g. ESEC `Id 13945`). Diffs two bienniums' `GetCommitteeMeetings`-derived cohorts (`MeetingCohortProvider` — archive-first: re-parses the closed window's archived SOAP wire offline via the same zeep binding, so an immutable docket isn't re-pulled weekly; live fallback only for an un-archived window) on the stable `Id`; the cohort name is the **clean `Name`** (#61 `observed_name`), not the agency-double-prefixed `LongName` stored as `Organization.name`, so the double-prefix never reaches PM and a PM canonicalisation can't false-fire. Same windowed emit + shared spine as #46, but **re-tuned guards** for a dormancy-prone cohort: low-overlap **off by default** (`--min-overlap-fraction` 0.0 — a body absent from one window is dormancy, not a wrong-biennium signal) and the storm fraction only weighed past `--storm-floor-min-overlap` (default 5). Window-absence ≠ rename (the diff intersects ids present in **both** windows). Weekly timer (Sun 07:45 UTC) + ad-hoc. Backfill caveat: the detector diffs current-vs-prior biennium, so an older rename (ESEC = 2023) needs a targeted `--biennium`
      validate_committees.py — read-only local↔PM validation CLI (#64): for each PM-linked produced org, diffs local canonical state ↔ live `OrgDetail` (`get_entity`) and buckets discrepancies (unlinked / missing / merged / name / acronym / names-window / acronyms / parent drift), splitting `reconciled` (PM curation roundtripped — e.g. a mirrored `former` window) from `divergent` (mirror lag/break). Emit-nothing; sequential reads + bounded `RetryableClientError` backoff; reports the unbaselined-fetch-event count. Exit 1 keys on `divergent`. `merged` is modeled but not live-detectable (PM's `get_entity` collapses a 404 without `merged_into`)
      committee_name_chain.py — pure full-timeline rename-chain builder (sub-project 3, Phase B): given `{biennium: {source_id: LongName}}` across all archived bienniums, walks each stable id's **consecutive appearances** and emits every `normalize_name` transition as a windowed `former`→`legal` hop (effective bounds = boundary biennium start, #58). Deep-history guardrails: normalize-before-compare (formatting churn ≠ rename), dormancy-aware (absence gap spanned), per-boundary rename-storm floor (systematic reformat dropped, recorded in `storm_skipped`). No DB/PM
      reconcile_committee_name_chain.py — Phase B emit CLI (sub-project 3): the deep-history counterpart of #46 — reads every archived roster via `CommitteeRosterCohortProvider`, builds the full chain (`committee_name_chain`), and emits each `former`/`legal` transition through the #46/#56 spine's per-row `_emit_names`. Classifies an absent id (hidden vs unproduced), reports storm-skipped boundaries, empty-archive abort. Emit-only (PM curates `is_canonical`; the #45 mirror brings windows back, now sticking via #65 fill-only). `--dry-run`; exit 0/1/2/3. Backfill-once (not a timer) — the daily/weekly #46/#56 detectors carry renames forward
      heal_committee_curation.py — one-shot force-adopt heal CLI (#65 Part 2): for the whole anchored produced cohort, re-fetch each PM `OrgDetail` and force-apply it via `OrganizationDescriptor.upsert_from_pm` + a clock-parity stamp — the PM-wins branch of `apply_record` run **unconditionally**, bypassing LWW. Unsticks committees left LWW-locked (local clock ahead of PM), so PM's curation (name/acronym/windows) is finally adopted; idempotent (no-op at parity). **Two distinct skew sources** it remedies: the pre-fill-only refresh (#65, the original) and the **anchor-stamp bump** (#109) — every row created before that fix landed ahead of PM's own clock by the delivery round-trip, so this is the convergence tool for an anchor-stamp-era org skew too (it is what closed the #109 chronic org row). Local `canonical` write (app role); read-only PM. Exit 0/2/3
      reanchor_assignments.py — one-shot natural-key anchor recovery CLI (#283). power-map#467's org merge migrated a role's assignments by copy-and-delete, reminting every ULID with no old→new map; power-map#469 restored the rows but not their ids. The sidecar cannot see this — an anchored assignment is addressed PM-natively by id and never re-matches, and `_heal_dead_anchor` leaves it alone because assignments can't identifier-rematch (`supports_rematch` False), logging `dead_anchor_unhealed` once per row per process with no aggregate; 138 rows sat stranded for two days. Clear-and-re-produce is the wrong repair (the rows exist upstream → duplicates), so this re-resolves the anchor on PM's own uniqueness key `(person, role, start_date)`: per role one paged `list_assignments_for_role` read, then re-anchor each local row absent from PM's id set whose `(person, start_date)` matches. No match → left alone, counted `unresolved` (clearing it would route the row to the CREATE path — the duplicate being avoided). Writes an `AnchorReanchor` ledger row per re-anchor (disposition `natural_key_reanchor`), the only durable handle on the dropped id; adopts PM's clock when the payload matches so the anchor write doesn't restart the #102 churn. Idempotent; `--role-source-id` scopes the sweep. App-role `canonical` write; read-only PM; `--dry-run`; exit 0/2/3
      heal_assignment_clocks.py — one-shot LWW-skew heal CLI (#102): the assignment analog of #65's committee heal, for the chronic assignment-clock ping-pong. A 2026-07-06 span backfill bumped ~4,300 anchored assignments' local `updated_at` ahead of PM, so the reconcile re-POSTs an *identical* observation every cycle forever (PM no-ops it without advancing its clock → 26,990 deliveries/10 days → PM 429s). For each anchored assignment whose local clock is strictly ahead of PM **and** whose observation wouldn't change PM (`AssignmentDescriptor.local_newer_is_noop`), adopt PM's `updated_at` (clock **only** — for assignments WE are the authority, unlike #65's curation adopt) → LWW parity, churn stops. A genuine pending change (observation differs) is **left** for the reconcile — the heal must never drop a real update. App-role `canonical` write; read-only PM; `--dry-run`; exit 0/2/3. The **durable backstop** is the `apply_record` local-newer no-op gate (below); this heal is the one-shot convergence of the existing skew
      supersede_rejections.py — one-shot outbox-backlog maintenance CLI (#258): moves each `REJECTED` entry that a later open `PENDING` entry for the same `(entity_type, local_id)` has replaced to the `SUPERSEDED` status added by migration `a1b2c3d4e5f6`. `REJECTED` is terminal by design — a blind retry just repeats the rejection, so `_REENQUEUE_BLOCKING_STATUSES` excludes it and the sidecar alerts when the count *rises* — and that leaves a gap: once the defect is fixed in code and the cohort re-enqueued, the old rejections stay `REJECTED` forever and hold the count static, which is exactly what the rise-alert reads as "nothing new", so the next real rejection hides in the pile. usa-wa's case was 1,788 rows across the #255 (null `identifier_type`) and #257 (`unknown_identifier_type`) waves, every one already re-enqueued. Only `PENDING` counts as a replacement (`DELIVERED` is another delivery's settled history, `UNAVAILABLE` is itself unsettled). Rows are **kept**, not deleted — the incident stays legible, it just leaves the operator's to-do count. Query lives in the portable `clearinghouse_sync_powermap.engine.maintenance`; app-role local write, no PM traffic, idempotent, `--dry-run` counts without writing; exit 0
      retract_assignments.py — one-shot producer retraction CLI (#144 Phase 2): given local assignment `source_id`s, retires each artifact tenure usa-wa produced (the Wynne LD39 Senate 2001-02 chamber-conflation + its paired party span) via power-map#391's `op:"retract"` on the assignment observation channel — POSTs `{identifier_type:pm_assignment_id, identifier_value:<ulid>, op:"retract"}` to `/api/v1/assignments/observations` (`op` rides the request model's `additional_properties`, the #111 pattern — no client regen), and on a `retracted` disposition tombstones the local row (`archived_at`, the reversible axis mirroring PM's archive — `_seat_scope` excludes archived rows so the `--sweep-biennia` audit clears). **Retraction is terminal** (power-map#391 shipped no reversible `archived:false`; un-retract is admin-only) — never build retry against un-retract; PM's anti-resurrection + the #144 Phase 1 derivation exclusion keep the phantom span from returning. An already-`archived_at` target (a completed prior run) is an idempotent `already_retracted` (no re-POST — resolve is full-natural-key `(source, source_id)` incl. archived, not `live_only`, so a re-run isn't mis-reported `not_found`); unanchored/not-found skipped-and-counted; a non-`retracted`/`auto-attached` disposition is `unexpected` + un-tombstoned. Transient 429/5xx retries on a bounded backoff (the heal pattern). App-role DML; `--source-id` (repeatable, required) + `--source` (default `usa_wa_legislature`) + `--dry-run` (resolves + previews WITHOUT POSTing — a retract POST is irreversible); exit 0 clean/idempotent · 1 a target unsettled (not-found/unanchored/refused) · 2 auth · 3 persistent transient PM outage (re-run). Run sidecar-paused
      prune_subscriptions.py — one-shot reclaim CLI (#73 Axis 1 step 6): the counterpart to `build_reconciler`'s mirror-set scoping. `sync_subscriptions` is additive (never unsubscribes), so the ~1,000 PM-only strangers the old whole-subtree walk registered stay subscribed-but-inert (feed delivers, reconciler fetch-then-skips). This diffs PM's `list_subscriptions` against the freshly-discovered mirror set (`SubscriptionReconciler.prune_subscriptions`) and `remove_subscriptions` the difference. Guarded against a discovery collapse: an empty desired-set (`empty_desired`) or a stale fraction over `--max-prune-fraction` (`prune_floor`, default 0.9 — permissive, since the first run legitimately removes ~half) aborts. Strangers have no local row, so nothing is evicted locally; idempotent. **Run-once**, not a timer.
```
