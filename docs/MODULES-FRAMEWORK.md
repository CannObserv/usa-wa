# Modules — Framework

Layer 1 (jurisdiction-agnostic primitives) and Layer 2 (the legislative-government
model). The reusable Layer-3 pattern these support is in
[ARCHITECTURE.md](ARCHITECTURE.md); the Layer-4 deployment is in
[MODULES-DEPLOYMENT.md](MODULES-DEPLOYMENT.md).

The canonical tier's Layer-1/2 half — the adapter runner and base, the Postgres provenance
spine and its integrity sweep, `raw_export`, `seed_manifest` and the canonical domain models —
was deleted in #412 PR F; what remains here is the job harness, the raw store, the identity
registry, the source/coverage tables and the pure span engine the pipeline builds on.

```
packages/
  clearinghouse-core/                 — Layer 1: framework primitives (jurisdiction-agnostic)
    src/clearinghouse_core/
      models.py       — Declarative Base, CreatedAtMixin, TimestampMixin (side-effect-imports jurisdictions + sources + registry + runs + source_coverage for Base.metadata)
      jurisdictions.py — `JurisdictionType` + `Jurisdiction` only: the FK target `sources.jurisdiction_id` names. Its writer is `usa_wa_common.seed_jurisdictions` asserting the local vocabulary (#310). The containment graph (`jurisdiction_relationships` + its type lookup) and the `pm_*_id` anchors were dropped in #412 PR F
      sources.py      — `Source` (one row per external feed; `/api/v1/sources` lists them and #180 coverage hangs off them) + `RetentionPolicy` (`operational_cache` | `archival`, #54 — declarative now: the raw store deletes nothing). Was `provenance.py` until #412 PR F, which dropped the rest of that spine (fetch events, payloads, citations, notes, document identifiers): fetched bytes live in the raw store, citations in the published `citations` dataset
      job.py          — **shared job harness** (#179): `run_job(name, handler, *, argv, extra_args, needs_db, commit, ledger, role, dry_run, dry_run_help)` owns the scaffold every operational CLI used to re-implement — env via the single `get_database_url()` path (not raw `os.environ`), engine lifecycle + disposal, base args `--dry-run`/`--json`, commit/rollback, summary emission, exit-code mapping, the #178 ledger row. Handler = `async def h(ctx: JobContext) -> JobResult | Mapping | dataclass | None`; the last three read as `ok` with those counters. **`degraded` is the point** — `JobResult.degraded(counters)` is terminal with its own non-zero exit so `OnFailure=` fires on a run that completed having accomplished nothing. Exits 0 ok / 1 failed / 2 config / 4 degraded; `JobResult(..., exit_code=)` preserves a job's established 3 = "aborted, took no action". A handler that raises records `failed` with `{}` counters unless it raises **`JobFailure(counters) from exc`** (#331): same `job_failed` traceback, rollback and exit 1, but the ledger row (`/health/jobs`) and the `job_finished` record keep how far the run got. The #49 email carries only its unit's last 25 journal lines, and the raw harvesters run first in `pipeline-nightly.sh`, so that script restates each failed stage's summary line as its closing lines (CR 5/6). Commits on ok **and** degraded (a skip-and-continue sweep's reached work is real), rolls back on `--dry-run` or failure. **Every operational CLI is an adopter** (#179b), each declaring a module-level `JOB_SLUG` (the ledger's stable identity, so a module can move without orphaning its run history), locked by `scripts/tests/test_job_harness_adoption.py` (every `python -m` module under `packages/*/src` calls `run_job`, declares a slug, and no two slugs collide — `/health/jobs` is `DISTINCT ON (job_slug)`); its exemption list is a named empty set, so the next daemon has to exempt itself deliberately. **`role="owner"`** resolves `DATABASE_URL_OWNER` (never falling back to the app DSN) and runs the whole job — ledger writes included — on a **per-run** engine built from it; its five adopters, one-shot migrations, were deleted in #412 PR F, so no job declares it now. A job whose commit is **not** conditional on success-or-dry-run keeps `commit=False` and its own transaction — the two operator CLIs flush their attestations to the raw store only after their own commit, and `operators/cli.py --list` commits even under `--dry-run`. A job that opens its **own** sessions takes the factory from `ctx.require_session_factory()`, never `get_session_factory()`, so it stays on *this run's* engine (CR #196 f49). **`--dry-run` must be honest** (f47/f55/f56): a `commit=False` job that never reads `ctx.dry_run` would commit under the flag, so such a job passes `dry_run=False` to decline it or `dry_run_help` to state a narrower meaning. Locked by `scripts/tests/test_dry_run_honesty.py`
      runs.py         — **job-run ledger** (#178): `JobRun` (`clearinghouse_core.job_runs`) `(id, job_slug, started_at, finished_at, outcome, counters JSONB, git_sha, host)`; `outcome` CHECK-constrained to `ok|degraded|failed`. `open_run`/`close_run` bookend the run on their own session (independent of the job's transaction), so a row left `finished_at IS NULL` is a job that never reported back — killed/OOM/hung past `TimeoutStartSec=` — which a write-at-the-end ledger can't represent; `record_run` is the fallback when the open failed, `normalize_counters` JSON-sanitizes a dataclass/mapping/None. Writes are best-effort — observability must not become a new failure mode. Staleness is a plain query, `(job_slug, started_at)` indexed. Mutable by design; classified in `scripts/tests/test_grants_append_only.py`
      source_coverage.py — **coverage as data** (#180): `CoverageClaim` (frozen dataclass — `source_slug`, `dimension`, `range_start`, `range_end`, `status`, `audited_at`, `notes`; `floor_year`/`ceiling_year` read the leading year off either a bare election year `2008` or a biennium label `1991-92`) + `SourceCoverage` (`clearinghouse_core.source_coverage`, one row per `(source_id, dimension, range_start)`) + `claim_for`/`known_gaps`/`seed_source_coverage`. `status` CHECK-constrained to `verified|assumed|absent`; **`absent` is the load-bearing one** — it makes a known gap (votewa 2020+) a fact rather than the silence a missing row is indistinguishable from, so the unique key is per-`range_start` and a served span coexists with an absent one on the same dimension. `dimension` keys the *axis* (WSL serves `sponsor_roster` from 1991-92 but `committee_membership` only from 1999-00). **The seam:** the claim is declared once per source in that adapter's `coverage.py` (pure Python, so a CLI floor derived from it needs no database for `--help`), and `seed_source_coverage` projects the same object into the table from `provisioning.py`, on both the get and the create path — run nightly by `usa_wa_pipeline.coverage_seed`; declaration and table cannot drift because they are one thing. `evidence_citation_id` was dropped with the citations table (#412 PR F). Mutable by design (a re-audit UPDATEs in place); classified in `scripts/tests/test_grants_append_only.py`
      rawstore.py     — **#302 raw-tier file store** (#304): content-addressed wire objects (`<root>/<source>/objects/<sha[:2]>/<sha256>` — the name IS the integrity baseline) + per-run JSON manifests (buffered, one atomic tmp+rename write on `close()`, so a crashed harvest leaves stray objects, never a partial ledger) + rebuildable `latest.json` (resource_id → newest ok fetch) for TTL decisions; `rebuild_latest` replays the manifests into a fresh one — how the #434 restore brings the index back, since the backup mirrors only objects and manifests. `put_object` dedups byte-identical re-fetches while the manifest still records the pull; `verify_store` re-hashes manifest-referenced objects with a `byte_budget` + `after` cursor seam. Root: `USA_WA_RAW_ROOT`. Archival sources — nothing here deletes
      raw_integrity.py — raw-store integrity sweep CLI (#304, `raw-integrity-sweep`): rolling byte-slice with its cursor at `<root>/.raw_integrity_state.json` (wraps at the tail), exit 1 on mismatch/missing (corruption/tamper — `failed`, never `degraded`), `--dry-run` = sweep without persisting the cursor, `--expect-objects` = exit 4 (`degraded`) on a missing or empty store instead of a clean pass. The weekly `usa-wa-integrity-sweep` unit's target since #412 PR C; it covers the operator attestations too, whose raw-store body is their only provenance
      registry.py     — **the identity registry** (#308): the #302 pipeline's only mutable state, deliberately jurisdiction-blind (opaque namespaced keys, one decision table; all WA knowledge stays in the matching rules that propose clusters). Three `registry`-schema tables: `entities` (persons+orgs by `kind`; `merged_into` = the adjudicated-merge tombstone the published crosswalk carries — PM's only re-point signal), `entity_keys` (natural key → entity, membership never decays), `adjudications` (the human decisions — the only path that moves or merges; sticky registry). `decide()` is the pure five-row decision table (mint/append/noop/conflict/sticky), `registered_view()` resolves merges to survivors, `apply_decision()` maps one verdict onto the tables (the nightly `usa_wa_pipeline.registrar` is its caller; `entity_id=` overrides the minted id). The operator tables (`operator_events`, `committee_succession_events`) share the schema but are modelled in Layer 2. Grants: schema enumerated in `scripts/grants.sql`
      testing.py      — test-side helpers shared across packages: `patch_job_runtime(monkeypatch)` (**mandatory before calling a harness `main()` in a test** — the harness otherwise resolves the *production* DSN), `parse_job_args` (the parser seam, since the parser is built inside the harness), the prod-DSN guard and the `db`-tier advisory lock (#208)
      db/             — ULID SQLAlchemy column type (see db/ulid.md for rationale)
      database.py     — Async engine + session factory
      config.py       — Settings / env access (pydantic-settings)
      logging.py      — configure_logging() + get_logger()
  clearinghouse-domain-legislative/   — Layer 2: the term calendar, the span engine, the operator overlay and its attestation models
    src/clearinghouse_domain_legislative/
      terms.py        — **the biennium term calendar** (#189, AR-14): `parse_biennium` / `biennium_for_date` / `biennium_start_year` / `biennium_start_date` / `previous_biennium` / `bienniums_in_range` — pure `YYYY-YY` label arithmetic, no wire, no session, so the span engine next door can do term algebra without importing a jurisdiction adapter. It lived in the WSL adapter until #189, which is a large part of how that adapter became a de-facto shared kernel
      tenure_spans.py — **the merged-span builder** (#78, promoted from the WSL adapter at #189): `Observation` → `TenureSpan`, grouping on `(member_id, kind, discriminator)`, splitting on dormancy gaps, resolving each run's `valid_from`/`valid_to`/`is_active` off `terms`. Pure — no DB, no source knowledge. Also `merge_party_continuity` (#289), the one exemption from the dormancy split: a member's same-party spans rejoin across ANY gap, because a break in elected service is evidence about a seat and not about an affiliation — blocked only by an attested span of a different party in between, which is a documented switch. Applied at the end of `apply_operator_events`, the single funnel every party-span builder already passes through
      operator_overlay.py — **the pure operator-succession span-boundary overlay** (#107, promoted at #189), run by the pipeline's conformed span builders. Detail: [MODULES-LEGISLATURE-SPANS.md](MODULES-LEGISLATURE-SPANS.md)
      seat_clipping.py — **counterpart clipping** (#360): a dated succession moves BOTH sides of the handoff, or neither. The overlay dates the span an event names; this closes the counterpart's biennium-derived edge onto the same boundary. Quantization is measured against the span's OWN biennium, never a Jan-1/Dec-31 pattern. Refuses — and reports — where both sides are dated, neither is, the predecessor outlives the successor (a merged #267 return tenure), or the clip would leave the successor's `start_biennium`. The same rule runs first on the **member axis** (#282), before the seat pass: a member's dated seating into a new seat closes their old seat's quantized ceiling (never an open one). Pure, idempotent, order- and length-preserving. Detail: [PIPELINE.md](PIPELINE.md#counterpart-clipping-360)
      span_kinds.py   — canonical tenure span-`kind` discriminators (#114): `KIND_PARTY`/`KIND_SENATE`/`KIND_HOUSE`/`KIND_COMMITTEE` + `SEAT_KINDS` (the seat subset) + `SINGLE_HOLDER_KINDS` (the chamber seats — the ones exactly one person holds at a time, which is what `seat_clipping` and the `assignments_seat_occupancy` gate both scope to). Defined **once** in the domain (Layer 2) and *imported* by every projector that emits spans (the WSL sponsor, committee-membership and roster projectors, `usa_wa_facts_seats.house.projector`), by the pipeline's conformed models and by `operator_events` (`SEAT_KINDS`) — so a rename lands in one place and the operator-event seat-kind guard can't drift from the builders. Cross-layer pin: `usa-wa-facts-seats/tests/test_span_kinds_guard.py`
      operator_events.py — `OperatorEvent` (`registry.operator_events` since #412, beside `adjudications`; #107): operator-attested mid-biennium succession events feeding the span overlay (a death/resignation/appointment no wire signal dates — the cumulative wire keeps a departed member named, so their span stays ghost-open). Three `kind`s split by scope — `departed` (person-scoped, no seat → closes EVERY open span: seat+party+committee), `vacated` (seat-scoped end → closes ONE named seat), `seated` (seat-scoped start → opens ONE named seat); a chamber move = `vacated`(old)+`seated`(new) on one member so party stays continuous. Natural-keyed on the `usa_wa_operator` Source + a deterministic `source_id` (`member:kind[:seat]:date`, so a re-ingest is idempotent + a corrected date is a distinct event); `superseded_by_id` self-FK for append-only date-corrections (provenance never mutated, #54). Written by `usa_wa_adapter_legislature.operators.store`; the nightly reads it through `usa_wa_pipeline.operator_read`
      committee_succession.py — `CommitteeSuccessionEvent` (`registry.committee_succession_events` since #412; usa-wa#124): operator-attested committee lineage links — `succeeded_by` / `split_from` / `merged_with` between era-`Id` committee orgs, one linked entity per event, optional `effective_year`. Same `usa_wa_operator` source, same append-only supersede. Written by `usa_wa_adapter_legislature.committees.succession_store`; published as the `org_lineage` dataset (#447)
```
