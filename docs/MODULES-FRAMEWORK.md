# Modules — Framework

Layer 1 (jurisdiction-agnostic primitives) and Layer 2 (the legislative-government
model). The portable Power Map sync engine and the generated PM client split out to
[MODULES-SYNC-ENGINE.md](MODULES-SYNC-ENGINE.md) at CR #196 (finding 62), when this
file reached 15.9k tokens against a 10k budget. The reusable Layer-3 pattern these
support is in [ARCHITECTURE.md](ARCHITECTURE.md).

```
packages/
  clearinghouse-core/                 — Layer 1: framework primitives (jurisdiction-agnostic)
    src/clearinghouse_core/
      models.py       — Declarative Base, TimestampMixin (side-effect-imports jurisdictions + provenance + sweep_state + runs + source_coverage for Base.metadata)
      jurisdictions.py — Jurisdiction cache mirror (4 tables: types/relationship_types lookups, jurisdictions, jurisdiction_relationships) — local copy of Power Map's Jurisdiction extension
      provenance.py   — Source, FetchEvent, RawPayload, Citation, Note, DocumentIdentifier (every canonical fact traces back to these)
      adapter.py      — BaseAdapter contract + FetchedPayload / NormalizedBatch / ResourceRef
      runner.py       — AdapterRunner: cache-or-fetch decision, idempotent upsert, provenance writing (derives FetchEvent.content_hash = sha256(RawPayload.body) — the #54 integrity baseline, single chokepoint). `archive_only(resource_id)` (#79) is the public promotion of the `_archive_payload` seam (#62): fetch + archive a wire **without** normalizing (honours the freshness cache), for a Phase-A harvest whose canonical derivation is archive-first + needs context the harvest doesn't hold (PDC's era roster)
      integrity.py    — provenance integrity sweep (#54): `python -m clearinghouse_core.integrity` re-hashes RawPayload bodies vs FetchEvent.content_hash; exit 1 on mismatch (corruption/tamper — `failed`, never `degraded`); NULL baselines = unbaselined, skipped. Weekly timer + OnFailure alert. Default run is a **rolling byte-slice** (#55): verifies `--byte-budget` (default 256 MiB) worth of payloads past a persisted ULID watermark (`sweep_state.py` / `clearinghouse_core.integrity_sweep_state`), wrapping at the archive tail — per-run cost flat as the #39 docket volume grows, whole corpus covered every ceil(bytes/budget) runs. `--full` = whole-corpus pass ignoring the cursor; `--limit N` = row-capped partial (`limited`). The cursor upsert is the sweep's one write (app-role DML on a non-provenance table; #54 REVOKE forbids a `verified_at` on RawPayload itself). Re-alert cadence: the cursor advances past a mismatch too, so a corruption emails once (#49 exit-1) then isn't re-reported until the next coverage cycle re-scans that slice — "no follow-up" = "not yet re-scanned," not "resolved". **Pilot adopter of the #179 harness** (`job.py`): `main()` is `run_job("integrity-sweep", …)`, so the run now lands a #178 ledger row and gains `--dry-run` (sweep, don't persist the cursor — the harness owns the commit) and `--json` (machine summary; the default is a `key=value` line, and the structured log record carries full counters either way). Exit codes unchanged — the weekly unit's `OnFailure=` is wired to exactly that 0/1
      sweep_state.py  — IntegritySweepState: single-row-per-scope rolling cursor for the integrity sweep (#55); `cursor` = highest verified RawPayload.id (ULID str) or NULL to start a fresh coverage cycle
      job.py          — **shared job harness** (#179): `run_job(name, handler, *, argv, extra_args, needs_db, commit, ledger, role, dry_run, dry_run_help)` owns the scaffold all ~47 entry points re-implemented — env via the single `get_database_url()` path (not raw `os.environ`), engine lifecycle + disposal, base args `--dry-run`/`--json`, commit/rollback, summary emission, exit-code mapping, the #178 ledger row. Handler = `async def h(ctx: JobContext) -> JobResult | Mapping | dataclass | None`; the last three read as `ok` with those counters, so an existing `RunSummary`/`HarvestSummary` migrates unchanged. **`degraded` is the point** — `JobResult.degraded(counters)` is terminal with its own non-zero exit so `OnFailure=` fires on a run that completed having accomplished nothing (today `results/harvest.py`'s total-outage WARNING has no consumer). Exits 0 ok / 1 failed / 2 config / 4 degraded; `JobResult(..., exit_code=)` preserves a job's established 3 = "aborted, took no action". Commits on ok **and** degraded (a skip-and-continue sweep's reached work is real), rolls back on `--dry-run` or failure. Since **#179b every operational CLI is an adopter** — 44 jobs, each declaring a module-level `JOB_SLUG` (the ledger's stable identity, so a module can move without orphaning its run history), locked by `scripts/tests/test_job_harness_adoption.py` (every `python -m` module under `packages/*/src` calls `run_job`, declares a slug, and no two slugs collide — `/health/jobs` is `DISTINCT ON (job_slug)`). The only exemption is the sidecar daemon `usa_wa_sync_powermap/__main__.py`, which `run_forever()`s and has no terminal outcome to record. #179b also added **`role=`**: `"owner"` resolves `DATABASE_URL_OWNER` (never falling back to the app DSN) and runs the whole job — ledger writes included — on a **per-run** engine built from it, for the five migrations that hard-delete citations the app role is REVOKEd on (#54). A job whose commit is **not** conditional on success-or-dry-run keeps `commit=False` and its own transaction — the WSL/SOS/PDC refreshes commit and *then* report an error count; `meetings/harvest.py`'s `--dry-run` means "skip the seed file", not "roll back the archive"; `operators/cli.py --list` commits even under `--dry-run`; the twelve PM producer CLIs interleave PM calls with local writes. A job that opens its **own** sessions takes the factory from `ctx.require_session_factory()`, never `get_session_factory()` — that is what keeps it on *this run's* engine, app today and the per-run owner engine the moment it declares `role="owner"` (CR #196 f49). **`--dry-run` must be honest** (f47/f55/f56): a `commit=False` job that never reads `ctx.dry_run` commits under the flag, so the five such jobs — the WSL/SOS/PDC refreshes and the PM `bootstrap` — pass `dry_run=False` to decline it outright, while `meetings/harvest.py` passes `dry_run_help` to state its narrower real meaning. Locked by `scripts/tests/test_dry_run_honesty.py` (every job declines the flag, lets the harness roll back, reads it, or is on an explicit write-free allowlist). **`testing.patch_job_runtime(monkeypatch)` is mandatory before calling a harness `main()` in a test** — the harness otherwise resolves the *production* DSN; `testing.parse_job_args(add_args, argv)` is the seam for parser tests now that the parser is built inside the harness
      runs.py         — **job-run ledger** (#178): `JobRun` (`clearinghouse_core.job_runs`) `(id, job_slug, started_at, finished_at, outcome, counters JSONB, git_sha, host)`; `outcome` CHECK-constrained to `ok|degraded|failed`. `open_run`/`close_run` bookend the run on their own session (independent of the job's transaction), so a row left `finished_at IS NULL` is a job that never reported back — killed/OOM/hung past `TimeoutStartSec=` — which a write-at-the-end ledger can't represent; `record_run` is the fallback when the open failed, `normalize_counters` JSON-sanitizes a dataclass/mapping/None. Writes are best-effort — observability must not become a new failure mode. Staleness is a plain query, `(job_slug, started_at)` indexed. Mutable by design; classified in `scripts/tests/test_grants_append_only.py`
      source_coverage.py — **coverage as data** (#180): `CoverageClaim` (frozen dataclass — `source_slug`, `dimension`, `range_start`, `range_end`, `status`, `audited_at`, `notes`; `floor_year`/`ceiling_year` read the leading year off either a bare election year `2008` or a biennium label `1991-92`) + `SourceCoverage` (`clearinghouse_core.source_coverage`, one row per `(source_id, dimension, range_start)`) + `claim_for`/`known_gaps`/`seed_source_coverage`. `status` CHECK-constrained to `verified|assumed|absent`; **`absent` is the load-bearing one** — it makes a known gap (votewa 2020+) a fact rather than the silence a missing row is indistinguishable from, so the unique key is per-`range_start` and a served span coexists with an absent one on the same dimension. `dimension` keys the *axis* (WSL serves `sponsor_roster` from 1991-92 but `committee_membership` only from 1999-00). **The seam:** the claim is declared once per source in that adapter's `coverage.py` (pure Python), the CLI floors are derived from it at import — argparse defaults must not need a database for `--help` — and `seed_source_coverage` projects the same object into the table from `provisioning.py`, on both the get and the create path; declaration and table cannot drift because they are one thing. Mutable by design (a re-audit UPDATEs in place); classified in `scripts/tests/test_grants_append_only.py`
      seed_manifest.py — frozen-seed tamper-evidence convention (#54): writes/verifies `.sha256` (sha256sum format) + `.meta.json` sidecars for checked-in seed files; `verified_digest()` is the ingest seam — verifies a seed then returns the raw digest a loader writes into FetchEvent.content_hash (git is the in-repo evidence; sidecars are for ingest outside git)
      rawstore.py     — **#302 raw-tier file store** (#304): content-addressed wire objects (`<root>/<source>/objects/<sha[:2]>/<sha256>` — the name IS the integrity baseline, as `FetchEvent.content_hash` was) + per-run JSON manifests (the FetchEvent analog; buffered, one atomic tmp+rename write on `close()`, so a crashed harvest leaves stray objects, never a partial ledger) + rebuildable `latest.json` (resource_id → newest ok fetch) for TTL decisions. `put_object` dedups byte-identical re-fetches while the manifest still records the pull (`skip_unchanged` parity); `verify_store` re-hashes manifest-referenced objects with a `byte_budget` + `after` cursor seam. Root: `USA_WA_RAW_ROOT`. Archival sources — nothing here deletes
      raw_integrity.py — raw-store integrity sweep CLI (#304, `raw-integrity-sweep`): the file-store successor to `integrity.py`, rolling byte-slice with its cursor at `<root>/.raw_integrity_state.json` (wraps at the tail), exit 1 on mismatch/missing (corruption/tamper — `failed`, never `degraded`), `--dry-run` = sweep without persisting the cursor. Runs beside the DB sweep until #302 cutover
      registry.py     — **the identity registry** (#308): the #302 pipeline's only mutable state, deliberately jurisdiction-blind (opaque namespaced keys, one decision table; all WA knowledge stays in the matching rules that propose clusters). Three `registry`-schema tables: `entities` (persons+orgs by `kind`; `merged_into` = the adjudicated-merge tombstone the published crosswalk carries — PM's only re-point signal), `entity_keys` (natural key → entity, membership never decays), `adjudications` (the human decisions — the only path that moves or merges; sticky registry). `decide()` is the pure five-row decision table (mint/append/noop/conflict/sticky), `registered_view()` resolves merges to survivors, `apply_decision()` maps one verdict onto the tables (`entity_id=` override = the seed's canonical-ULID preservation). Grants: schema enumerated in `scripts/grants.sql`
      raw_export.py   — one-shot RawPayload corpus export CLI (#305, `rawpayload-export`): payload-bearing FetchEvents → the raw store, hashes verified against `content_hash` BEFORE landing (mismatch raises + fails the run — corruption is the DB sweep's finding, never laundered); NULL baselines exported + marked `unbaselined`; payload-less events (dedup shares, #59) skipped; resumable by FetchEvent id via `<root>/.rawpayload_export_state.json`. Read-only on Postgres — table drops are #314's, gated on this verification
      db/             — ULID SQLAlchemy column type (see db/ulid.md for rationale)
      database.py     — Async engine + session factory
      config.py       — Settings / env access (pydantic-settings)
      logging.py      — configure_logging() + get_logger()
  clearinghouse-domain-legislative/   — Layer 2: legislative-government model (state/federal)
    src/clearinghouse_domain_legislative/
                      — Bill, Legislator, BillAction, StatuteSection, etc. (skeletoned step 7)
      identity.py     — Person/Organization/Role/Assignment + LifecycleMixin (archived_at + deleted_at tombstones — PM archived/deleted axis split, #38/#42) + Organization.active (PM's third axis: operational live/dissolved domain flag — orgs-only, NOT a live-read gate, #43) + OrganizationName (dated name variants mirrored from PM `OrgName`/power-map#239; `Organization.name` stays the resolved current scalar, this child table is the history/association surface, #45) + OrganizationAcronym (acronym variants mirrored from PM `OrgAcronym` — list distinct from names, no type/dated window; `Organization.acronym` stays the resolved current scalar — read mirror adopts PM's `is_canonical` acronym into it symmetric with `name`, #47/#65) + `Role` **seat model** (power-map#261/#263, usa-wa#68): a legislative seat is a durable Role keyed on the structural tuple `(organization_id, role_type, jurisdiction_id, qualifier)` — House = 2 seats/LD (`qualifier` "Position 1"/"Position 2"), Senate = 1 seat/LD (`qualifier` NULL). `Role.jurisdiction_id` (the seat's district, distinct from the org binding-root dropped in the 2026-06-09 decoupling) + `Role.qualifier` are the seat columns; uniqueness splits into two partial indexes — `uq_roles_seat` `(org, role_type, jurisdiction, qualifier)` WHERE jurisdiction NOT NULL (NULLS NOT DISTINCT) for districted seats, `uq_roles_org_name` `(org, name)` WHERE jurisdiction NULL for title-keyed committee/leadership roles. **One-row-per-PM-anchor invariant (#86, from the #84 postmortem)**: each of the four PM anchor columns (`pm_person_id`/`pm_organization_id`/`pm_role_id`/`pm_assignment_id`) carries a **partial unique index** `WHERE <col> IS NOT NULL` (`uq_<table>_pm_<col>`, replacing the old plain lookup index — a unique index serves reads too). A second local row stamped with an existing anchor (PM dedups observations on `(person, role, start_date)`, so two local rows can resolve to one PM assignment — the #84 armed a crash loop with 98 such pairs) now fails loudly at write time instead of silently arming a reconcile crash days later. The one-shot span-collapse migrations (`migrate_spans`/`migrate_pdc_spans`/`migrate_committee_spans`) retire the pre-#86 duplicates. They are now all **index-safe** — each retires a stranded row (deleting it + citations to free its anchor) **before** moving that anchor onto the covering span (`migrate_pdc_spans._retire_onto` #91, `migrate_committee_spans` #95, `migrate_spans._retire_onto` #97) — so they run **under the live index**, not only before it lands. Their tests run under the live index too (the sponsor tests dropped the module-level `drop_anchor_unique_indexes` at #97); only the specific pre-index-modelling cases (two local rows sharing one anchor at rest, which the index forbids) still opt into the `drop_anchor_unique_indexes` fixture per-test
      role_types.py   — `RoleType` catalog mirror (power-map#268, usa-wa#68): local read-only cache of PM's role_types catalog (`GET /api/v1/role-types`) — `{slug, display_name, expects_jurisdiction, requires_qualifier}` keyed on slug (power-map#271/usa-wa#70 renamed the field from `is_seat`). The sync descriptor reads `expects_jurisdiction` to decide a Role observation's shape (seat-mode structural tuple vs title-mode) at runtime, retiring the hardcoded seat-slug map. `requires_qualifier` (power-map#273/usa-wa#71) is PM's **enforced** flag — a districted-seat observation of such a type (e.g. `state_representative`, per-position) without a `qualifier` is `REJECTED("qualifier_required")` rather than minting a positionless seat (#267); the descriptor mirrors it to defer such a seat pre-flight (`state_senator`=False → NULL qualifier valid). Refreshed by the sidecar's catalog sync ([`role_type_catalog.py`](../packages/usa-wa-sync-powermap/src/usa_wa_sync_powermap/role_type_catalog.py) → `sync_role_type_catalog`, first cycle + hourly cadence)
      queries.py      — live_only(): read-side liveness guardrail (archived_at + deleted_at IS NULL) every live read routes through (#38/#42)
      cohorts.py      — **the cohort-provider seam, as Protocols** (#189, AR-14): `CitationTarget` (the `(fetch_event_id, fetched_at, resource_id)` tuple every span cites, defined here because it is the *provider* seam's vocabulary and re-exported by `span_emit` where callers already import it), plus `AttestedCohortProvider[K]` (`citation_events()` — what makes a provider citable), `BienniumCohortProvider` (`cohort(biennium) -> {source_id: name}` — the input contract the two committee rename reconcilers already share a diff over) and `ArchivedBienniumCohortProvider` (+ `archived_bienniums()` — the rename chain's domain). `runtime_checkable`, so `scripts/tests/test_cohort_seam.py` can assert each concrete provider still conforms; presence-only checking is the point, since a renamed accessor silently unsubstituting two sources is exactly the regression #189 found (see [MODULES-COMMON.md](MODULES-COMMON.md) § The seam). Deliberately **several small Protocols, not one** — the seven providers key on three different things and return four different row shapes, so a single `CohortProvider` would erase to `Any` and prove nothing; jurisdiction-specific cohort shapes live next to their vocabulary in `usa_wa_common.ballot`
      terms.py        — **the biennium term calendar** (#189, AR-14): `parse_biennium` / `biennium_for_date` / `biennium_start_year` / `biennium_start_date` / `previous_biennium` / `bienniums_in_range` — pure `YYYY-YY` label arithmetic, no wire, no session. Layer 2 already models the biennium as *data* (`LegislativeSession.biennium_label`, `classification='biennium'`); this is the arithmetic that goes with the column, so the span engine next door can do term algebra without importing a jurisdiction adapter. It lived in `usa_wa_adapter_legislature.synthesis` — the WSL *anchor synthesizer* — purely because that is where the first caller needed it, which is a large part of how the WSL SOAP adapter became a de-facto shared kernel: pdc, sos and sync-powermap all reached into it for date arithmetic (one of them for an underscore-private name)
      tenure_spans.py — **the merged-span builder** (#78, promoted from the WSL adapter at #189): `Observation` → `TenureSpan`, grouping on `(member_id, kind, discriminator)`, splitting on dormancy gaps, resolving each run's `valid_from`/`valid_to`/`is_active` off `terms`. Pure — no DB, no source knowledge
      span_emit.py    — **the generic span→Assignment emitter** + `close_stale_spans` (#82/#83, promoted at #189) + `load_context_spans` (usa-wa#267 — the members' spans **another builder owns**, read-only, for the `departed` split's cross-seam return search; scoped to the members carrying a `departed` and to kinds this builder does not own, `end_biennium` mirrors `start_biennium` since the Assignment does not store it and only the validity bounds are read), `retire_unasserted_spans` (#228 — the closed-row counterpart, for historical builders whose rows strand on re-derivation rather than departure). Detail: [MODULES-LEGISLATURE-SPANS.md](MODULES-LEGISLATURE-SPANS.md)
      operator_overlay.py — **the pure operator-succession span-boundary overlay** (#107, promoted at #189). Detail: [MODULES-LEGISLATURE-SPANS.md](MODULES-LEGISLATURE-SPANS.md)
      span_kinds.py   — canonical tenure span-`kind` discriminators (#114): `KIND_PARTY`/`KIND_SENATE`/`KIND_HOUSE`/`KIND_COMMITTEE` + `SEAT_KINDS` (the seat subset). Defined **once** in the domain (Layer 2) and *imported* by every Layer-3 builder that emits spans (`sponsor_observations`, `committee_membership_observations`, `pdc_observations`, the two House migrations) and by `operator_events` (`SEAT_KINDS`) — so a rename lands in one place and the operator-event seat-kind guard can't drift from the builders. Cross-layer pin: `usa-wa-adapter-sos/tests/test_span_kinds_guard.py`
      operator_events.py — `OperatorEvent` (`canonical.operator_events`, #107): operator-attested mid-biennium succession events feeding the span-builder overlay (a death/resignation/appointment no wire signal dates — the cumulative wire keeps a departed member named, so their span stays ghost-open). Three `kind`s split by scope — `departed` (person-scoped, no seat → closes EVERY open span: seat+party+committee), `vacated` (seat-scoped end → closes ONE named seat), `seated` (seat-scoped start → opens ONE named seat); a chamber move = `vacated`(old)+`seated`(new) on one member so party stays continuous. Natural-keyed on the `usa_wa_operator` Source + a deterministic `source_id` (`member:kind[:seat]:date`, so a re-ingest is idempotent + a corrected date is a distinct event); `superseded_by_id` self-FK for append-only date-corrections (provenance never mutated, #54)
```
